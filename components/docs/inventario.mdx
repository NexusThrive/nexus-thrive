# Inventario

**Sistema compartido (`components/`), documentado aquí:** 31 átomos, 47 moléculas,
38 organismos, 6 plantillas y 3 proveedores.

## Capa de interacción

Lo que toda pantalla usa para abrir, confirmar, explicar y avisar. No se recrea en los módulos.

| Necesito… | Componente | Nivel |
| --- | --- | --- |
| Diálogo o panel lateral genérico | `ResponsiveSheet` (`drawer`, `size`, `busy`) | Organismo |
| Formulario en diálogo / en panel lateral | `FormDialog` / `FormDrawer` | Organismo |
| Confirmar una acción | `ConfirmDialog`, `useConfirm()` | Organismo |
| Ventana flotante compacta | `Popover` | Molécula |
| Ayuda "?" | `ContextHelp` | Molécula |
| Nombre de un botón de icono | `Tooltip` | Molécula |
| Campo con etiqueta, descripción y error | `Field`, `FieldError`, `FieldDescription` | Molécula |
| Resultado de una acción | `useToast()` | Molécula |
| Error o aviso dentro del formulario | `Alert` | Molécula |
| Nada que mostrar / esperando una sección | `EmptyState` / `LoadingState` | Molécula |
| Esperando la página | `PageSkeleton` | Organismo |

## Componentes de módulo (`app/**/_components`)

Son organismos de dominio: cargan o mutan datos con Server Actions, así que viven junto a su
ruta. Usan el sistema (botones, campos, `PageHeader`, `EmptyState`, `ResponsiveSheet`). Lo que
queda por extraer o migrar:

| Módulo | Pendiente | Prioridad |
| --- | --- | --- |
| Construcción · obra | Formularios en línea de Lean, bitácora, avance y cotizaciones de la obra → diálogo; `DataTable` con selección y orden | Alta |
| Catálogo APU | `FilterBar` (búsqueda + chips + orden), `ImportProgress` | Alta |
| CRM | `SwipeRow` (acciones al deslizar en móvil), `BulkBar` | Media |
| Finanzas | `AmountKeypad` y recibo imprimible | Media |
| Reservas | `TimeSlots` sobre `WeekStrip` y `MonthCalendar` | Media |
| Todos | Formularios que aún arman su propio pie y errores → `FormDialog`/`FormDrawer` | Media |
| Configuración, Onboarding, Panel CEO | Ya usan el shell y la capa de interacción | Baja |

**Criterio:** un componente sube a `components/` cuando un segundo módulo lo necesita o cuando
es un patrón del sistema. Cada uno llega con su historia.
