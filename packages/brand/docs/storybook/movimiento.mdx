# Movimiento

Todo nace de la N: el trazo recorre el contorno, el texto entra con enfoque como THRIVE en el
logo y los cortes caen con el ángulo de 24°. El movimiento **explica** (de dónde viene algo,
qué cambió, que se guardó); nunca adorna sin motivo.

## Escala

| Token | Duración | Para |
| --- | --- | --- |
| `--d1` | 120 ms | Microinteracciones (presionar) |
| `--d2` | 200 ms | Hover, color, bordes |
| `--d3` | 320 ms | Paneles, barra lateral |
| `--d4` | 600 ms | Entradas de vista |

## Diálogos y paneles

- Entran con `--motion-overlay-in` y salen con `--motion-overlay-out`; la hoja móvil sube con
  un rebote corto.
- El contenido se lee durante la transición y el foco no espera a la animación.
- Abrir y cerrar rápido varias veces no rompe el estado.

## Piezas con dueño propio

Cada transición tiene **un solo dueño**: no se combinan CSS, Web Animations y una librería sobre
el mismo elemento. La tabla completa está en `DESIGN.md` §4.

| Pieza | Dueño | Notas |
| --- | --- | --- |
| Skeleton (`.nx-sk`) | CSS | Gris suave con un barrido tenue de brillo de 1,7 s; sin ángulos |
| Hueco al arrastrar una oportunidad | CSS (`nx-gap`, `nx-gap-x`) | Crece desde 0 y las tarjetas de abajo se corren con él |
| «Cargando» en un enlace (`LinkPendingHint`) | CSS (`nx-link-pending`) | Aparece tras 140 ms de espera y solo cambia la opacidad |
| Casillas nativas | CSS | La marca se dibuja con `scale`, 220 ms |
| Desplazamiento con inercia | `SmoothScroll` | Dos filtros en cascada para rueda y trackpad; táctil y teclado quedan nativos |
| AURI al crear el negocio | View Transitions | `<ViewTransition name="auri-onboarding">` en el onboarding y en la cinemática, clase `nx-auri`, `--d4` |
| Barra superior y abrir una app | View Transitions | Solo estos casos; los modales siguen con su morfeo |

## Rendimiento

- **Cero librerías de animación.** El artifact usaba GSAP, Motion y AutoAnimate; aquí todo es
  CSS o Web Animations API (corren en el compositor, sin JS por cuadro).
- Solo se animan `transform`, `opacity`, `filter` y `clip-path`.
- Los resortes se **precalculan** (`lib/experience/motion/spring.ts`) y se reproducen como keyframes.
- Contadores y odómetro escriben en el DOM sin re-renderizar React.
- Un solo listener delegado para presión, foco de luz e imán (`MotionProvider`).

## API (`lib/experience/motion`)

| Función | Qué hace |
| --- | --- |
| `spring(el, "scale" \| "x" \| "y" \| "rotate", from, to)` | Resorte físico |
| `shake(el)` | Sacudida de error |
| `flash(el)` | Destello oro de dato que cambió |
| `drawPath(path)` | Dibuja un trazo SVG |
| `burst(x, y)` / `burstFrom(el)` | Lluvia de cortes oro y tinta |
| `reveal(elements)` | Entrada escalonada |
| `withThemeSweep(apply)` | Cambio de tema con barrido a 24° |
| `motionOff()` | ¿Hay que apagar el movimiento? |

Atributos: `data-press` (se hunde y rebota), `data-press="card"` (más sutil), `data-mag`
(imán, CTA principal), clase `nx-spot` (foco de luz), clase `nx-rise` con `--i` (entrada
escalonada).

## Reducir movimiento

`prefers-reduced-motion` o **Ajustes → Reducir movimiento** (`<html data-motion="off">`)
apagan todo: CSS en `app/styles/motion.css` y JS vía `motionOff()`. Los contadores muestran
el valor final de inmediato.

## Modales que nacen del botón

En PC los diálogos de `ResponsiveSheet` se abren con un morfeo desde el botón que los activó
(380 ms, con enfoque) y se cierran hacia él. Es automático para `FormDialog`, `FormDrawer` y
`ConfirmDialog`; no se reimplementa. Sin botón de origen visible, o con movimiento reducido,
entra la animación centrada. Guía completa: `packages/brand/docs/04-patrones/movimiento.md`.
